# Книжные Reels: пополнение запаса

Прямое решение автора3ноября2026: **3книжных ежедневно + голосовой дополнительно
через день**. Начало4ноября. Аккаунт только `@mairova_a_a`, репозиторий
`zairush8877-sys/repetitor`, веткаmain. Книжные10:00/14:00/19:00МСК; исходные
15голосовых слотов остаются на09:00 и своих датах. После каждой публикации —
полный видео-репост вStories. Пользователь разрешила подготовку, пополнение
очереди и публикацию в этом конкретном формате без отдельного согласования
каждого следующего тематического текста. Новые платные сервисы этим не разрешены.

## Владение процессами

Доставкой владеет только существующий GitHub Actions `publish.yml`, общий
`instagram-publishing-${github.repository}` concurrency и `publish.js --one`.
Heartbeat этого чата пополняет медиа/явные слоты, сам ничего вInstagram не
отправляет, не делаетupload_probe, не создаёт нового sender и не меняет cron.
Одна отправка за запуск; лимит3classic+1voice в его день проверяется поочерёдно
по рабочим квитанциям и живой истории. Статусыunknown/partial/pending Stories
сначала сверяются; опубликованное не повторяется. Ночной/междневной догонки нет.

## Начало каждого пополнения

ПрочитатьAGENTS.md, этотrunbook и свежий журнал. Локальная корневая очередь47
устарела; не копировать её вmain. Сначала прочитать текущийmain, активный календарь,
очередь,prepared/reposts manifests и последниеActions/квитанции. Сохранить отдельный
снимок иexpected head. Не возобновлять вручную остановленные автоматики.

Цель — **следующие7полных календарных дней по3готовых approved/published книжных
слота** на каждый день. Учитывать реальную датуEurope/Moscow, не закрывать пропуски
прошлых дней новыми отправками. Считать уникальныеpostId, а не файлы/Stories.
Если21слот уже обеспечен готовыми файлами и нет сбоя, ничего не менять и молчать.
Обычно требуется добавить3на новый седьмой день. Прежние голосовые слоты, даты,
статусы и опубликованные квитанции сохранять полностью. После исчерпания13оставшихся
голосовых не создавать голос автора и не повторять старые видео: сообщить о нехватке
новых исходников, книжная серия остаётся отдельной задачей.

## Редакция и экспорт

Работать отдельной папкой `outputs/classic-refill-YYYY-MM-DD/`, сохраняя прошлые.
Брать рендер `outputs/cadence-variation-2026-11-03/build-classic.cjs` и его runtime как проверенную
основу. Для новой папки скопировать runtime/assets; заменить только путьOUT/выбранных
активов в своей копии. Не изменять accepted ранниеMP4 и корневые dirty-файлы.

Книжные фотографии, IBM Plex Serif/Mono, разные классические произведения, строки по
одной. Без «Маирова АА»,handle и нижнего офера обэкзаменах/услугах. Связанные
языковые темы, ЕГЭ/ОГЭ и олимпиадные авторские разминки. Не выдумывать истории
учеников, баллы, новую официальную программу/год/номерзадания. Использовать
незанятые темы редакционного банка, проверив все опубликованные иapproved материалы,
включая вложенныеslides/rows. Текстовый непроизведённый черновик сам по себе не дубль.

Роли `.claude/workflows/post-factory.js` выполняются доступными агентами Codex:
стратег+копирайтер(2подписи), независимый корректор по первичным словарным/учебным
источникам, редактор. Сохранить источники и конкретные оговорки. Для обычного
школьного материала сохраняетсяschool:true и одна единица в календарную неделю;
ЕГЭ/ОГЭ не входят в эту квоту. Не обходить её ложной маркировкой. В неделе4–8ноября
school-слот уже занятclassic03, в неделе9–15 — classic07. Дальше выбирать уместные
олимпиадные разминки без превращения всех публикаций в школьный урок.

Дата/UTCscheduledAt/campaignId должны быть назначены ДО prepared draftKey.
После исправлений даты пересчитать только соответствующий draftKey, не менять
побайтовую копию уже готового медиа без причины. Новый выпуск: MP4H.2641080×1920,
30fps,AAC48kHz, полное видеоStories, coverOffset/готоваятаблица. Обязательны декод,
права на фото и конкретную запись, громкость, проверка каждой ячейки и живых кадров
на390px: верх300,низ260safe, без обрезки/пересечения колонок. Итоговые фото не
выдавать за личные фото Анны. Не заявлять человеческое прослушивание/каждыйкадр,
если таких проверок не было.

Штатный актуальный `check-content.js` запускать отдельно на каждый новыйID и
в объединённой с реальным main очереди; использовать правильныйMEDIA_CONTENT_DIR.
Локально ffmpeg — `/private/tmp/mama-reels-tools/ffmpeg` при его наличии; при переносе
проверить путь заново. Зеленый check не заменяет редакторскую/визуальную проверку.

## Внесение вmain

Добавлять только новые approved посты,prepared/reposts entries, медиа и явные
`additionalSlots` в существующуюcampaign. Верхнееcadence остаётся
`{startsOn:'2026-11-04',classicTimes:['10:00','14:00','19:00']}`. Все прежние объекты,
первичные15slots и квитанции сравнить с актуальным исходным снимком. Проверить3слота
в день иschool-квоту по вычисленным датам. Публикационный код обычно менять не нужно.

Коммит делать атомарно черезGit-data API от прочитанногоmain. Перед перемещением
ветки ещё раз проверитьhead/lease, толькоfast-forward, безforce. Еслиmain изменился,
перечитать очередь/доставку, пересобрать merge и проверки; не затирать новую квитанцию.
`outputs/cadence-2026-11-03/stage-public.py` — только первая миграция114→129с изменением
6дат, **не применять его повторно** для обычного пополнения. Upload-helper тоже требует
новогоmanifest/QA иexpectedhead; готовыйстарыйmanifest не переиспользовать.

После изменения получить actual `publish.yml` dry_run=true/upload_probe=false,
дождатьсяsuccess ипроверки всехявныхмедиа. Этотaudit ничего не публикует. Расписание
иготовыйфайл не равныInstagram ID. Сохранить короткий журнал, хеши/коммит/слоты/
подтверждения. Обычное успешное пополнение выполнять без сообщения пользователю;
сообщать о реальном сбое, нехваткеисходников или требуемом решении. Доставку проверять
по текущим квитанциям/Actions до любых повторов.

Heartbeat выполняется локально вCodex и требует доступногоMac/приложения. Сам
GitHub-публикатор работает в облаке; семидневный готовый запас снижает зависимость
публикации от одного локального запуска.

## Постоянная смена фона и музыки · новое решение 3 ноября

Пользователь прямо попросила: «и фон меняй и музыку менять постоянно».
У соседних книжных роликов должны различаться и photoId, и musicId, включая
границу между двумя партиями и двумя днями. Не начинать новый пакет с повторения
последних использованных активов. Текущие каталоги — photos-rotation.json и
music-rotation.json в outputs/cadence-variation-2026-11-03: восемь фото и семь
разных произведений. Проверять actual SHA файлов, точный audio offset/crop и
их включение в render cache key. Новые источники добавлять с такими же правами
и проверками. На старом единственном Бахе не останавливаться. Фотографии —
иллюстрации, их не выдавать за личные снимки Анны. Credits брать у конкретной
выбранной записи; не приписывать всем композитора/исполнителя первого трека.

## Статус фонового пополнения

На3ноября2026 это подготовленная инструкция, **активного heartbeat пополнения нет**.
Для создания ежедневного фонового процесса, который будет добавлять новые материалы
в GitHub, требуется отдельное явное разрешение пользователя. Действующий облачный
публикатор и готовая первая неделя от этого не зависят. Проект предложения:
outputs/cadence-2026-11-03/refill-automation-draft.json. До разрешения не создавать
пополнение через другой инструмент или обходной cron.
