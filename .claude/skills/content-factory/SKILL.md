# Фабрика контента

Контент готовит не один автор, а команда специалистов через воркфлоу — так
принято в этом проекте всегда («нужно подключать всегда всех для подготовки»).

## 1. Обязательный процесс: команда, а не соло

Для любого поста запускать воркфлоу `.claude/workflows/post-factory.js`
(Workflow tool, `scriptPath`). Команда:

- **СММ-стратег** — заголовки, хештеги, что усилить (получает статистику аккаунта);
- **Копирайтер** — 2 варианта подписи по правилам тона;
- **Корректор** — проверка КАЖДОЙ пары/факта по орфографическому словарю РАН
  (Грамота.ру). Аккаунт принадлежит учителю русского языка: одна фактическая
  ошибка стоит репутации. Этот шаг не пропускается никогда;
- **Редактор** — сводит финальную версию, объясняет что изменил.

Args воркфлоу: `{ draft: {kicker, title, rows, caption, hashtags, rubric, format}, context: "..." }`.
В `context` обязательно перечислять: недавние посты (не повторяться) и
персональные запреты автора (см. §5).

Результат фабрики показать пользователю ВМЕСТЕ с картинкой-превью и
объяснением, что изменила команда и почему.

## 2. Правила тона (нарушение = переделка)

- Запрещённые клише: «Признавайтесь…», «Сохраните, чтобы не потерять»,
  «А вы знали?», «Друзья!», «Готовы? Поехали!», «Спойлер:», риторические
  вопросы-приманки.
- Эмодзи: максимум один на подпись, лучше ноль. Хештеги: 2–4, узкие.
- Тест: если фразу могла написать любая нейросеть про любую тему — переписать.
- Подпись: сильная первая строка → фактура (история слова, живая деталь) →
  спокойное завершение без призыва-штампа.
- Личное бьёт безличное: история ученицы дала 8 498 охвата против 37–295 у
  постов «про правила». Где можно — просить у автора живую деталь от первого лица.

## 3. Форматы по данным аккаунта (@mairova_a_a)

| Формат | Что даёт | Факт |
|---|---|---|
| Таблица «неправильно → правильно» на один экран | репосты | эталон 18,3 тыс. ♥ у конкурента; наш Reels в этом формате — лучший старт |
| История ученика («Было → стало») | доверие, заявки | 8 498 охвата — аномалия аккаунта |
| Вопрос с двумя вариантами на обложке | комментарии | люди отвечают не дочитав |
| Этимология знакомых вещей | выход за аудиторию родителей | вход через еду/бренды |
| Картина + современная реплика | репосты через юмор | лучший shares-показатель у конкурента |

Посты «объяснение правила» — слабейший формат (37–295 охвата), вес снижен.

## 4. Продакшен

- **Посты/карусели**: `node render.js <id>` (слайды 1080×1350 в content/images/,
  превью content/preview.html). Слайд-таблица: `layout: "table"` + `rows`.
- **Pinterest**: `node render.js --pin <id>` → 1000×1500 (2:3) в content/pins/.
- **Reels**: `node render-reels.js <id>` (1080×1920, 30 к/с, MP4 с музыкой).
  Быстрое превью финального кадра: флаг `--frame`. Безопасные зоны: сверху
  300px (шапка Instagram с ником), снизу 150px (подпись и кнопки) — контент
  за них не выходит.
- **Сторис**: банк `content/stories.json`, рендер `node render-stories.js`
  (`--next` — только следующая), публикация `node publish-stories.js`,
  ежедневный запуск — workflow `stories.yml` (10:00 МСК). Каждая сторис — два
  кадра: вопрос/интрига и ответ, плюс собранное из них видео `<id>.mp4`
  с музыкой; публикуется именно видео, кадры остаются запасным путём.
  Безопасные зоны шире, чем у Reels: сверху 300px, снизу 260px (поле
  «Отправить сообщение»). Интерактивные стикеры (опросы, викторины, ссылки)
  через API недоступны — викторина собирается двумя кадрами.

### Обязательное оформление (нарушение = переделка)

- **Фон меняется всегда.** Руками в посте его не задают: рендер сам берёт
  вариант из `content/bg/index.json` по хешу id — так фон разный у разных
  постов и один и тот же при повторном рендере одного. Пополнять ротацию:
  `node gen-bg.js` (новый вариант = один HTML-шаблон в VARIANTS; тёмные
  перечислять в DARK, иначе тёмный заголовок пропадёт на тёмном фоне).
  Тетрадная клетка идёт только деталью в углу: под текстом она съедает
  контраст. На фотофоне таблица всегда лежит на белой карточке.
  Нейросетевые фоны (Higgsfield) — только если есть кредиты; СГЕНЕРИРОВАННЫЙ
  ТЕКСТ НА КАРТИНКАХ НЕДОПУСТИМ (тарабарщина на странице учителя).
- **Музыка обязательна во всём, что движется** — и в Reels, и в сторис:
  немое видео в ленте читается как сбой звука. Берётся из
  `content/music/index.json` тем же хешем. Пополнять: `node fetch-music.js`
  (скачивание с Викисклада) и `node fetch-music.js --prepare` (нарезка
  сорокасекундных фрагментов на самом громком месте — у классики вступления
  тихие и для короткого ролика мертвы). В библиотеку идёт только
  общественное достояние и CC0: CC BY требует подписи под каждым постом,
  CC BY-SA заражает своей лицензией готовое видео. Трендовые звуки Instagram
  через API недоступны — только вручную из приложения.
  ffmpeg — из devDependency ffmpeg-static.
- **Музыка всегда бодрящая и эпичная** (правило автора): хрестоматийные
  кульминации — Григ, Мусоргский, Россини, Бетховен, Вагнер. Ноктюрны и
  прочее спокойное в библиотеку не брать. У каждой записи в index.json
  обязательны поля composer и piece (по-русски) — без них не собрать подпись.
- **Композитор указывается всегда** (правило автора): в Reels — строкой
  «♪ Композитор — пьеса» в подписи (собирает publish.js из поля music,
  которое рендер записывает в очередь), в сторис — той же строкой на самом
  кадре, потому что подписи у сторис нет. Метаданные пьесы проверять:
  под запрос «финал Седьмой симфонии» однажды пришёл финал Третьей,
  и подпись была бы ложной.
- **Музыки в статичном посте быть не может** — у картинки в ленте нет
  звуковой дорожки. Нужен звук — формат должен быть Reels.
- **Шрифты**: `node fetch-fonts.js`, подключение — модуль `fonts.js`.
  Golos Text в заголовках, Manrope в таблицах, Caveat только на пометки.
  Системными шрифтами не рендерить: в headless-Chromium кириллицы почти нет,
  и всё сваливается в одно начертание.

## 5. Персональные правила автора (Анна)

- Пара «одеть/надеть» — не использовать: контекстно-зависима.
- Спорные словарные пары (риэлтор/риелтор) — не брать: магнит для склок.
- Заголовки/кикеры не выше безопасной зоны, фон яркий, слова выделены
  колонками «✕ Неправильно / ✓ Правильно».
- Музыка — только бодрящая и эпичная, композитор указывается всегда (см. §4).
- Обложка Reels в сетке — финальный кадр с полной таблицей: рендер пишет
  coverOffsetMs в очередь, публикация передаёт его как thumb_offset.
  Без этого Instagram выбирает кадр сам, и в сетке висит пустой заголовок.
- Фоны-фотографии автора лежат в content/bg/foto-*.jpg («тёмная академия»,
  папка автора в Google Drive, август 2026); новые добавлять через карту
  PHOTO в gen-bg.js с пометкой светлый/тёмный. Ротация (rotation.js) чередует:
  фотографии автора чаще (вес ×2), между ними рисованные fon-* — «нужно
  разнообразие» (правило автора). Примерно каждая третья сторис — на чистой
  палитре без снимка; для Reels есть режим plainBg (бежевая бумага, буквы
  прямо по фону) — назначать руками, когда пост просит спокойной подачи.
- Таблицы в ленту выходят ТОЛЬКО как Reels — с анимацией зачёркивания и
  музыкой. Статичный пост-картинка допустим лишь там, где анимировать нечего
  (после «Слова-призраки» 09.08: «нет музыки, нет анимации» — переделка).
- После каждой публикации в ленту publish.js сам репостит её в сторис
  (финальный кадр Reels или первый слайд) — подписчики видят анонс и там.

## 6. Публикация — только по явной команде

- Очередь: content/queue.json (pending → approved → published). Одобрение
  словами в чате; БЕЗ явного «публикуй» ничего не выпускать.
- Публикует GitHub Action `publish.yml` (workflow_dispatch, inputs post_id,
  dry_run) с секретом IG_ACCESS_TOKEN. Файлы должны быть на main —
  raw.githubusercontent.com/<owner>/<repo>/main/... (кэш 5 мин: после merge
  сверить Content-Length с локальным размером).
- Статистика: workflow `stats.yml` → `node publish.js --recent` (охват, лайки,
  ссылки последних постов).
- Заменить опубликованное нельзя: удаление — только руками в приложении,
  затем публикация новой версии.
- Токен и путь его получения: скилл `instagram-api-token`.

## 7. После сборки

Каждый результат прогнать через контроль качества (скилл `my-skill-instmom`):
сначала `node check-content.js`, затем смысловой чек-лист по кадрам. Только
после этого: закоммитить и запушить в рабочую ветку, превью отправить
пользователю (SendUserFile), спросить одобрение. Правки автора («мама права»)
применять без споров и фиксировать в §5 этого скилла.
